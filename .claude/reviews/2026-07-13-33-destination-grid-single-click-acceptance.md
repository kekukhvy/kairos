```java
@Test
void rowClick_invokesOnView() {
    DestinationGrid grid = new DestinationGrid(jsonMapper);
    List<DestinationDTO> viewed = new ArrayList<>();
    grid.setOnView(viewed::add);
    DestinationDTO destination = destination();
    grid.setRows(List.of(destination));

    fireRowClick(grid, destination);

    assertThat(viewed).containsExactly(destination);
}

// --- helpers ---

private static DestinationDTO destination() {
    return new DestinationDTO("dest-kafka-1", "KAFKA", null, NOW);
}

private static void fireRowClick(DestinationGrid grid, DestinationDTO destination) {
    String itemKey = grid.getDataCommunicator().getKeyMapper().key(destination);
    ComponentUtil.fireEvent(grid,
            new ItemClickEvent<>(grid, true, itemKey, null, 0, 0, 0, 0, 1, 0, false, false, false, false));
}
```

The test fires a synthetic single-click `ItemClickEvent` (click count `1`, no double-click
wrapping) directly at the grid and asserts `onView` is invoked with the clicked row — this
only passes if `addItemClickListener` (not `addItemDoubleClickListener`) is registered,
because `ItemClickEvent` is the event type `addItemClickListener` subscribes to.

The only reference to double-click anywhere under `kairos-admin/src` is in the
**generated Vaadin frontend runtime**, not project code:
```
kairos-admin/src/main/frontend/generated/jar-resources/gridConnector.ts:562:
  grid.addEventListener('dblclick', (e) => _fireClickEvent(e, 'item-double-click'));
```
This is Vaadin's own client-side connector (a vendored/generated file under
`generated/jar-resources`), which unconditionally wires a browser `dblclick` listener for
*any* Vaadin Grid regardless of whether the Java side subscribes to it — it is framework
plumbing, not application code, and is untouched by this change. Since
`DestinationGrid` no longer calls `addItemDoubleClickListener` on the Java side, no
`item-double-click` server-side listener exists to react to that event; a double click is
observed only as two ordinary single clicks, each independently invoking `onView` once (no
distinct/duplicate behaviour). Confirmed by AC1's test that a single click alone already
triggers `onView`.

`ScheduleGrid` currently use an icon-button actions column with no row-click behaviour at
all, which is a different interaction model from `DestinationGrid`'s row-click-to-open. This
is not a regression introduced by this change (it predates it — those two files are untouched
here); it reflects that the three grids have not yet been unified onto one interaction
pattern. Per the task instructions, this is recorded honestly as **satisfied once the grids
are unified onto a single click-to-open pattern** (tracked separately — issue #26 is
referenced in the new test's Javadoc as prior art for the pattern, but is not present on
this branch); `DestinationGrid` now matches the *target* single-click pattern, it does not
yet match the *actual current* behaviour of `TaskGrid`/`ScheduleGrid`. Marked **PARTIAL**,
not PASS, because "identically" is not yet true of the code as it stands.
